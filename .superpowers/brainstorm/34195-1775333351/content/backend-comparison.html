Backend: Supabase vs Firebase

Compared against Ayurplex MVP requirements

Requirement 🟢 Supabase 🟠 Firebase
Database PostgreSQL — relational, SQL, great for structured med schedules, user-calendar relationships, adherence tracking. Complex queries are trivial. Firestore (NoSQL) — document-based. Medication schedules with nested time windows and calendar links get awkward. Querying across collections requires denormalization.
Auth ✅ Email, Google, Apple, phone. Row-level security (RLS) policies built into Postgres. ✅ Same providers + anonymous auth. Security rules are a separate JSON config — powerful but verbose.
File Storage
(Prescription upload)		 ✅ S3-compatible storage with access policies. Direct upload from client. Generates signed URLs. ✅ Cloud Storage with security rules. Very similar capability.
Push Notifications
(Med reminders)		 ⚠️ No built-in push. Need Edge Functions + FCM/APNs or a service like OneSignal. More setup, but flexible. ✅ FCM built-in — Firebase Cloud Messaging is best-in-class. Scheduling, topics, conditional delivery. Huge win for a reminder app.
Serverless Functions
(AI scheduling logic)		 ✅ Edge Functions (Deno/TypeScript). Deploy alongside DB. Can call OpenAI/Claude APIs for smart scheduling. ✅ Cloud Functions (Node.js). Mature, well-documented. Cold starts can be slow on free tier.
Realtime
(Future: caregiver sync)		 ✅ Built-in Postgres realtime subscriptions. Subscribe to row changes. ✅ Firestore onSnapshot — excellent realtime. Slightly better DX for realtime use cases.
Calendar Integration
(Google Calendar API)		 Neutral — both require OAuth + Google Calendar API. Supabase stores tokens in Postgres (easy to query/refresh). Neutral — same OAuth flow. Firebase stores tokens in Firestore (harder to batch-query for scheduled jobs).
Pricing Free tier: 500MB DB, 1GB storage, 500K edge fn invocations. Pro: $25/mo. Free tier: 1GB Firestore, 5GB storage, 125K fn invocations. Blaze: pay-as-you-go.
Vendor Lock-in 🟢 Low — open source, self-hostable, standard Postgres. Can migrate to any Postgres host. 🔴 High — proprietary. Firestore data model doesn't transfer. Migrating away is painful.
Data Model Fit 🟢 Excellent — medications, schedules, calendar events, adherence logs are highly relational. SQL joins, aggregations for insights/trends are natural. 🟠 Adequate — works but requires denormalization. The "Insights" dashboard (adherence trends, category analytics) would need composite indexes or aggregation pipelines.

My Recommendation

A

Supabase (Recommended)

Ayurplex's data is deeply relational — meds → schedules → calendar events → adherence logs → insights. SQL is the natural fit. Push notifications need extra setup (OneSignal or FCM via Edge Functions), but that's a one-time cost vs. fighting NoSQL for every query. Open-source means no lock-in.

B

Firebase

Best choice if push notifications are the #1 priority and you want zero setup for FCM. But the NoSQL data model will create friction for the relational med-schedule-calendar data, and vendor lock-in is real. Better suited for chat apps and social feeds than structured health data.
